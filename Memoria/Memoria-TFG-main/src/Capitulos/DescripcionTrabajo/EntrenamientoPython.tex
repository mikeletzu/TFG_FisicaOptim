\subsection{Apartados de la ejecución}

Dada su flexibilidad para interactuar con la ejecución y la capacidad de visualicar los resultados claramente, se ha elegido IPython Notebook (.ipynb) como formato de código en el que trabajar con los modelos. Cada tipo de modelo se ha creado en un archivo distinto, si bien todos comparten la misma estructura.

\begin{enumerate}

    \item \textbf{Carga y procesamiento de datos}: 
    Los datos se leen del archivo .csv utilizando la librería pandas. Esta permite llevar a cabo la limpieza de estas fácilmente. 
    \begin{itemize}
        \item Se eliminan el primer y el último frame registrados;el primero no tiene un antecesor apartir del cual deducir el movimiento y el último no tiene el siguiente frame necesario para confirmar su posterior predicción.
        \item Se elimina la columna "frame"  de la tabla ya que no aporta información pertinente para el aprendizaje. Su función es meramente auxiliar para debugear.
        \item asímismo, en los casos que se explicarán más adelante, en los que muchos de los parámetros registrados no son necesarios, se filtran esas columnas para no sobrecargar innecesariamente el dataset.
    \end{itemize}
    Tras hacer la limpieza de los datos estos se transforman al formato de tensores de Pytorch. 

    \item \textbf{Dataset de Pytorch}: Pytorch ofrece dos clases base con las que ordenar y gestionar los datos que requiere el modelo. \textit{torch.utils.data.Dataset} almacena las muestras y sus etiquetas correspondientes, y \textit{torch.utils.data.DataLoader} permite un fácil acceso a las muestras. En este bloque se definen las carácteristicas del Dataset en base a las necesidades del modelo; este recibe en su constructora el tensor con la información filtrada y el tamaño de los lotes en los que dividirlo.

    \item \textbf{Estadísticas de normalización}: Se dividen los datos entre el entrenamiento y las pruebas, generalmente en un ratio de 80/20 respectivamente. Se itera sobre los datos de entrenamiento para calcular los deltas (movimientos de cada punto en cada frame) y se normaliza tanto el input completo como los deltas generados. La normal y la desviación típica tanto del input como del target se guardan el un archivo de formato JSON, para utilizarlo posteriormente en la integración en Unity.

    \item \textbf{Modelo de Pytorch}: Pytorch ofrece también una clase base apartir de la que implementar sus modelos de redes neuronales, \textit{torch.nn.Module}. En este apartado se extiende esta clase a las especificaciones deseadas y se genera utilizando el DataLoader mencionado un primer batch de prueba.
    
    \item \textbf{Entrenamiento}: En este apartado se determinan los parámetros de ruido que añadir al dataset o las iteraciones que hacer sobre él. El entrenamiento consiste en una fase de train y otra de test, en la que se observa el aprendizaje del modelo através de la caida del error medio de la posición de cada vértice.

\subsection{Los modelos}
Como se ha mencionado previamente, hay dos nociones principales que han guiado el desarrollo de este proyecto; por un lado, seguir el ejemplo de las investigaciones citadas en el estado del arte, combinando las técnicas más óptimas y por otro, el objetivo de priorizar la simplicidad y accesibilidad de nuestro modelo. Por lo tanto, a la hora de empezar con el entrenamiento, se optó por empezar por una red neuronal muy sencilla y apartir de ahí ir aumentando la complejidad en base a los resultados, problemas y limitaciones que fueran surgiendo. \newline

El modelo inicial es un perceptrón multicapa (MLP) sencillo con una sola capa oculta, este infiere la diferencia de desplazamiento entre un frame y el siguiente. Utilizando un dataset que genera lotes que contienen pares de [frameInfo, frameInfo + 1], se pasa el frame normalizado al modelo y este predice el delta de desplazamiento para cada vértice, desnormalizando este delta se calcula la posición inferida por el modelo y la diferencia entre esta y la posición real recibida en el frameInfo + 1 se utilizan como pérdida para el entrenamiento. La función de pérdida elegida inicialmente, MSELoss, se utiliza generalmente en problemas de regresión ya que penaliza fuertemente las diferencias grandes entre la predicción y el valor real, alineandose con nuestro objetivo. Las dimensiones del modelo son 13 de input (los parámetros de cada punto), el número de neuronas en la capa oculta (inicialmente entre 64 y 128) y 3 de output (el delta de desplazamiento en cada eje). \newline

El entrenamiento de este modelo recalca ciertos factores, algunos muy obvios como ampliar el tamaño de la red neuronal y otros menos evidentes que se recogen a continuación.

    \item \textbf{Sistema de coordenadas:} El registro de las posiciones al generar el dataset puede hacerse tanto de manera local respecto al pivote de la tela, como de manera global respecto al espacio 3D. Al registrar los elementos como las posiciones de los vertices o el sdf se hace de manera consistente, manteniendo un origen común para las coordenadas, por lo que ambos métodos son funcionales. Sin embargo, tras evaluar el desempeño del modelo con datasets relativos a ambos sistemas de coordenadas, se decide trabajar en espacio local, utilizando como origen la propia tela; de esa manera, las posiciones son más coherentes para el modelo y el resultado no es dependiente de la traslacion en el espacio 3D.

    \item \textbf{Frecuencia de muestreo:} Inicialmete el dataset se entrena con una serie de frames que se registran en intervalos predefinidos a la hora de hacer la simulación base. Este método agiliza la tarea de generación del dataset y podría pensarse que simplifica la simulación para el modelo. Al contrario, al disminuir el tiempo de intervalo del registro de frames se aprecia una mejora en el entrenamiento del modelo. Se concluye que el modelo aprende idóneamente con la máxima cantidad de frames posibles. Esta afirmación es respaldada por estudios como \cite{santesteban2022snug} en los que se utilizan grandes datasets con secuencias de animaciones.
    
    \item \textbf{Recurrencia:} Varias de las investigaciones del estado del arte mencionan como limitación las telas más dinámicas, ya que, al tener muchas menos restricciones, las mallas que no van pegadas a un cuerpo de colisión son mucho más susceptibles a la inercia. Naturalmente, el aprendizaje de estas propiedades físicas requiere del conocimiento de atributos como la velocidad o la aceleración de las particulas. Si bien valores como la velocidad eran parte del input, la recurrencia le permite al modelo tener una memoria a corto plazo del movimiento de cada vértice, haciendo su entrenamiento mucho más eficaz. En este caso se implementa una red neuronal recurrente (RNN) que sigue la arquitectura de tipo "many to one", es decir, una cantidad determinada de frames se utilizan como input para general el delta de desplazamiento entre el último frame de la secuencia y el que sería el siguiente.\newline

\end{itemize}
    
\subsection{Parametricación}
En el apartado del Dataset se han enumerado todas las caracteristicas de la tela que se guardan en la simulación. Si bien se registran todas para poder tener un margen de acción a la hora de entrenar los modelos, a lo largo del proyecto se han utilizado distintas técnicas para reducirlas y determinar cuales de ellas son esenciales.

\begin{itemize}
    \item Siguiendo la linea de la simplicidad, se reduce la cantidad de features utilizados al mínimo: la posición de cada vertice y el sdf. Se observa que en modelos sencillos, como la geometría de 6 vertices con el movimiento linear del colisionador esto resulta ser un método conveniente. La poca cantidad de parámetros reduce la duración del entrenamiento y optimiza su incorporación a Unity, de la que se hablará más en la próxima sección.

    \item Tras confirmar que la reducción de features puede ser interesante, se implementa un modelo random forest para ver cuales son los parametros más importantes para la inferencia. Como se ve en la figura, los parámetros U, V y MD resultan no ser importantes para generar la predicción. Sin embargo, se aprecia la importancia de los parámetros de velocidad. En este caso es más notable en el eje X, esto se debe a la configuración de la simulación con la que se ha generado el dataset analizado para el gráfico.
        \begin{figure}[H]

De forma que la red neuronal óptima recibe como parametros la posición de los vértices, la velocidad y el sdf. Aunque esto mejora el aprendizaje del modelo, en el proximo apartado se valorará si el coste adicional de utilizar la velocidad en Unity lo compensa.
